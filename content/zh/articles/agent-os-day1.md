这篇记录的是 10 月 2 日的实验。第一天主要想把一个简单任务跑完整：在网页里输入“移动到盒子上方”，让 Agent 根据相机画面找到盒子，再调用规划和执行，让机械臂移动过去。

Agent OS 想做的是一个统一的机器人操作入口。切换机器人之后，仍然可以在网页里看相机画面、发送任务、查看执行反馈。这一天主要测试的是机械臂，其他机器人没有在这轮实验里重新验证。

*这是后面跑通的黑色盒子案例，约 53 秒。指令是“移动到带白色标签的黑色盒子上方”。视频完整保留工作台界面，包括相机画面与 Agent 交互。这里只做悬停，没有抓取。*

## 先让机械臂完成一次运动

一开始没有直接让 Agent 识别物体，而是用了提前确定的目标位置和规划好的路径，先检查机械臂能不能完整执行。

这一步也不是直接就能跑。中间碰到了驱动和控制程序没有运行的问题，需要恢复连接，在示教器上启动控制程序之后才能执行。连接恢复后，机械臂用了二十多秒移动到白色盒子上方。随后复位，再执行了一遍，并录下了相机视频。

两次运动都完成了。从画面看，夹爪停在盒子上方，但是否正好居中、距离盒子多高，当时没有准确测量。

## 接到 Agent 上，还需要现场定位

接下来把复位和移动接到 Agent，通过自然语言调用。Agent 可以读取机械臂状态，然后选择动作执行。

不过这个版本仍然使用提前准备的目标和路径。虽然可以通过一句话启动，但盒子移动之后，原来的动作就不能直接用了。所以继续把相机定位和现场规划接进去，让 Agent 根据当前画面找到目标，再从机械臂当前的位置重新规划。

白色盒子的第一次尝试没有成功：视觉结果不够一致，系统停止了，没有执行运动。调整后再试，Agent 找到了盒子，规划并执行了新的路径。最后的相机画面显示夹爪停在盒子上方，但仍有几厘米左右的偏心。

到这里，白色盒子的案例已经不需要提前保存它的位置和运动轨迹了。不过现场标定还是比较粗，不能据此认为定位已经足够准确。

## 黑色盒子失败了几次

换成黑色盒子之后，接连遇到几个问题，并不是同一个原因一直没有解决。

最早一次是彩色图和深度数据没有正确对应，拿不到目标位置。重试又碰到视觉模型请求超时，等待很久之后仍然失败。后来分别处理了数据同步和请求耗时的问题。

还有一个小黑盒子放得比较远。它可以被定位，但位置超出了机械臂的可达范围，规划没有通过，也没有执行运动。

带白色标签的黑色盒子则是另一种情况：视觉已经找对了物体，但测量区域包含了盒子的顶面、侧面和背景，原来的检查一直认为结果不可靠。换成更详细的描述也没有解决，因为这次问题不在物体名称，而在后面的几何处理。

调整这部分之后，定位测试可以通过，随后在网页里重新发送指令，机械臂完成了悬停。上面的视频就是这次运行。

所以这一天的结果是：白色盒子和带标签黑色盒子都跑通了，但中间有失败和修复，还没有做足够多的连续测试。

## 网页和录像也有一些问题

除了运动本身，还花了时间处理网页连接。最初页面一直显示等待机器人，机器人服务实际上已经连接，问题出在浏览器对实时连接的支持上。换到支持的浏览器之后，画面和 Agent 对话可以正常显示。

录像也踩了坑。文件保存下来了，但在播放器里看起来像静止画面。检查后发现视频内容还在，保存格式和播放器兼容性有问题，最后转成兼容格式才正常播放。

这两件事没有改变机械臂的运行结果，但确实影响了操作和回看。后面还需要把这部分做稳定，避免每次演示都要额外处理。

## 今天的结果和后续安排

目前网页指令、现场定位、运动规划和真实机械臂执行已经在这几个案例里接起来了。复位也测试过，但定位精度和重复成功率还没有系统评估。

下一步先改善标定，实际测一下机械臂停在哪里、离物体多远。然后换几个物体和摆放位置，连续运行，记录成功、失败和拒绝执行的情况。

抓取暂时还没测。当前运动也需要现场人员监督，环境检查还不完整。Day 1 先把移动到物体上方这件事跑通，后面再继续补。
