Agent 直接驱动机器人时，最需要人参与的时刻是动作执行之前：它要去哪里、会扫过什么空间、是否应该现在做。上一阶段的 Agent OS 已经能在仿真中完成多步操作任务，并用仿真真值自动判定结果；这一阶段我们补上了“人在回路”的部分：动作在执行前先被预演，由人在任意一个界面上批准，整个过程可以实时观看，也可以事后逐步回放。

下面的视频是实拍：Agent 在仿真中完成“把桌上所有红色方块放进白色区域”，屏幕上是实时的数字孪生，手里是一块口袋设备。每个抓取与放置动作执行前，屏幕上先出现橙色的“幽灵”机械臂沿规划路径预演，设备同时提示审批；按住设备按键 1.2 秒后，真实（仿真中的）机械臂才跟上去。

## 审批是一层抽象，而不是某个界面的功能

我们没有把审批做在某一个界面里，而是放在 Agent 与机器人之间：

- **何时需要审批**由机器人的构型定义决定。仿真默认自动执行，真机默认逐个动作审批；运行时也可以改为仿真同样逐个审批。
- **审批请求**由 Agent 内核的扩展发出，进入一个本地的审批中心（Hub）。终端、网页和口袋设备都是它的“审批端”，**先回答的生效**，其余端立即收到结果并关闭提示。
- **仿真与真机走同一条路径**，区别只是一个标记：真机请求在所有界面上以红色标出“REAL ROBOT”。

这样做的好处是，增加一个新的审批端（比如手机或手表）不需要改动 Agent 或机器人，只需接入同一个审批中心。硬件急停仍然是独立的物理通道，不经过这套软件。

## 先看见未来：动作执行前的预演

审批的前提是看得懂要批准的是什么。只给出参数（“抓取 (-0.446, 0.043, 0.049)”）并不够，人需要看到动作会怎样发生。

因此在动作提交审批之前，仿真先在当前物理状态的副本上把这个动作完整执行一遍，记录轨迹，然后把世界恢复原状，不留任何痕迹。页面据此画出幽灵机械臂、沿途的残影与指尖路径。由于物理过程是确定的，预演就是真实的未来：我们核对过，随后真正执行时，末端位置与预演终点在毫米级一致。这个预演接口只提供给审批端，不对 Agent 开放，因此不改变 Agent 可用的工具，也不影响评测结果。

## 一个页面：实时与回放

数字孪生页面同时承担实时观看和事后回放：

- **实时**：仿真把每一帧的关节角、夹爪开度和物体位姿推送给页面，页面按到达顺序播放。仿真本身比真实时间快得多，页面会自动加速播放并在数秒内追上，保证动作连贯且不落后于 Agent。
- **Agent 循环**：左侧按对话的形式展示 Agent 的推理（流式更新）、它对人说的话、每一次工具调用与结果，以及每次审批由谁作答。
- **回放**：任务结束、真值判定完成后，同一页面载入完整记录，转为可拖动的回放；拖到任意时刻，左侧只显示到那一步为止的推理与调用，并标出当前这一步。
- **发起任务**：页面本身可以选择任务、修改指令、选择是否逐个动作审批，然后开始运行。修改过的指令不做自动判定，因为检查器只认得原任务的目标。

## 口袋里的审批端：AI Passport

我们选用了 FoloToy 的 AI Passport 作为硬件审批端。它是一块开源（[固件仓库](https://github.com/folotoy/ai-passport)，MIT 许可）的 ESP32-C3 口袋设备，有一块 240×320 的屏幕、三个按键、扬声器和电池，支持 USB 与低功耗蓝牙。我们为它重新编写了应用固件，界面沿用数字孪生的视觉语言：

- **实时页**：一个 9×9 点阵状态字形（思考、观察、执行、等待审批、完成），当前指令和步数。
- **审批页**：有动作待批时覆盖在最上层。按住确认键 1.2 秒批准，下键拒绝；真机请求以红框显示。短按不会触发，避免误批。
- **成绩页与宠物页**：近期的评测成绩和判定记录；一个像素小机器人，心情随近期成功率变化，知识包每进化一代就“升一级”。

设备只解析简单的文本命令，中文等任意文字由电脑渲染成小图后发送，因此设备不需要中文字库。它既可以用 USB 连接，也可以通过蓝牙无线使用。

## 实测

我们用真实的 Agent（DeepSeek 模型）在仿真中运行，并开启逐个动作审批：

- **分拣任务**（把所有红色方块放进白色区域）：Agent 共请求 12 次动作，全部在口袋设备上批准；其中一次放置失败，Agent 重新观察后自行重试。约 3 分钟完成，仿真真值判定通过，没有碰到其他物体，也没有碰撞桌面。之后的回放与仿真记录的最终位置相差不到 1 毫米。
- **叠放任务**：多次运行均通过判定。其中一次全程以蓝牙连接设备，审批请求与文字经蓝牙送达，设备状态随任务同步更新；这次的批准由网页端给出。

## 工程上的几处修正

把系统从演示推进到可用，修正了几处问题，记录如下：

- **观察时不再无谓地挪动机械臂。** 仿真原先在每次拍照前都把机械臂移出视野再移回。改为先判断机械臂是否真的遮挡了物体或标记区域，只在遮挡时才移开，并且只在姿态属于任务状态（例如正夹着物体）时才移回。在一次分拣任务的复现中，观察阶段机械臂的移动距离从 41 米降到 8 米，判定结果不变。
- **设备的动画曾占满处理器。** 图形库对放大的图片计算重绘范围时，会在四边对称地扩展，导致每一帧动画都重绘大半个屏幕。把每张放大的图片放进一个大小恰好的容器后，重绘范围被限定，蓝牙的启动时间从数秒降到一秒以内。
- **数据链路需要流控。** 设备的 USB 驱动在接收缓冲满时会直接丢弃数据。图片改为分块发送、逐块确认后，连续传输不再出错；蓝牙也沿用同一机制。
- **打开串口会让设备复位。** macOS 打开串口时信号线的先后顺序恰好构成了芯片的复位信号。调整顺序后，连接不再重启设备；链路中断时，电脑端会自动重连。
- **蓝牙带宽。** 文字图改为每像素 4 位透明度、由设备着色后，数据量降为原来的四分之一；再配合更大的链路层数据包和更短的连接间隔，一张文字图的传输时间从约 1.8 秒降到约 0.35 秒。

## 局限

- 视频中的机械臂是仿真；预演依赖仿真对动作的确定性复现。真机的预演需要接入真机自己的规划器，尚未完成。
- 低功耗蓝牙连接目前未加密。电脑端只连接首次配对的设备，防止同名设备冒充审批端，但链路本身仍应升级为加密配对，才适合用于真机审批。
- 设备的续航尚未测量。
- 视频中设备以 USB 连接；蓝牙连接已在相同任务上验证，但不是这段视频。
